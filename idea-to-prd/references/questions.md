# 追问清单

目标:用问题把粗想法变成可判断、可评测、可进入原型探索的产品定义。一次问 2-4 个问题,不要把整张表一次性丢给用户。

## 第一轮:把问题问出来

优先问:

1. 这个产品/功能主要给谁用?
2. 他们在什么场景下会遇到这个问题?
3. 现在他们怎么解决?最不满意哪里?
4. 如果只能解决一个问题,你最想先解决哪个?

可用选择题:

> 这个想法更像是哪类问题?
> A. 提升效率
> B. 降低决策成本
> C. 自动化重复工作
> D. 改善体验/转化
> E. 还不确定

## 第二轮:把方案边界问出来

优先问:

1. 用户第一次使用时,最小闭环是什么?
2. 第一版必须支持哪些动作?哪些可以不做?
3. 是否已有竞品或替代方案?你想避开什么?
4. 有没有业务、技术、合规或资源约束?

## 第三轮:把验证方式问出来

优先问:

1. 能不能给 3-5 个最典型的用户 case?每个 case 里用户是谁、处境是什么、会怎么问/怎么操作?
2. 对这些 case 来说,什么输出算好?什么输出绝对不能出现?
3. 做完后看什么指标说明方向对了?
4. 哪个假设最危险,一旦错了产品就不成立?

## 第四轮:把 Eval 问出来

AI 产品必须追问:

1. Dataset:这些 sample 覆盖哪些用户类型、场景和难度?还缺哪类 case?
2. Rubric:评价好坏时,安全/准确/完整/个性化/可执行的优先级是什么?
3. Metric:哪些指标能量化完成标准?阈值是多少?
4. Judge/Evaluator:谁来判断?人工、专家、LLM-as-a-Judge、规则程序,还是线上 feedback 校准?
5. Protocol:评测时是否允许联网、工具调用、多轮追问、人工确认?采样几次?是否盲评?

## 判断是否问够

至少能回答下面 7 个问题,才进入 PRD v0 输出:

- 谁用?
- 为什么现在需要?
- 解决哪个具体问题?
- 用户怎么完成核心流程?
- 第一版做什么/不做什么?
- 代表性 samples 是哪些?
- 什么输出算好,什么输出不可接受?
- 用什么 metric 判断完成?
- 哪些假设还没验证?
- 怎么判断值得继续?
