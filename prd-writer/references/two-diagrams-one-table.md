# 两图一表在 PRD v1 中怎么细化

PRD v0 的两图一表是产品定义材料;PRD v1 要把它们转成可开发、可测试、可验收的模块。

两图一表指:

1. 图一:原型草图 / 低保真结构图。
2. 图二:流程/状态图。
3. 一表:数据表,可以是业务对象表、指标表、评测样本表、漏斗表、权限表。

## 总体转换规则

| PRD v0 材料 | PRD v1 要写成什么 |
| --- | --- |
| 原型草图 | 页面/组件清单、信息架构、模块说明、CTA、空/错/加载状态 |
| 流程/状态图 | 主流程、节点说明、状态机、异常路径、回退策略 |
| 数据表 | 字段定义、枚举、校验、接口、埋点参数、测试数据 |
| Samples/Eval | demo 场景、Rubric、验收标准、测试集/评测集 |
| Metric | 目标值、统计口径、埋点、上线验收 |

## 图一:原型草图 -> 页面与模块说明

每个页面/区域按下面模板写:

| 模块 | 写法 |
| --- | --- |
| 模块名称 | 页面顶部、左侧上下文、主结果区、操作栏、详情抽屉等 |
| 用户目标 | 用户进入这个模块要完成什么任务 |
| 展示内容 | 静态文案、动态数据、列表字段、引用证据、提示 |
| 数据来源 | 用户输入、后端接口、LLM 输出、缓存、第三方系统 |
| 主操作 | 主 CTA 和次级操作,例如采纳、编辑、重试、升级 |
| 状态 | 默认、加载、空、成功、失败、禁用、权限不足 |
| 边界 | 超长文本、缺字段、多条记录、无结果、网络失败 |
| 验收 | 模块出现条件、字段完整性、交互结果 |

### 示例:AI 工单助手

| 模块 | 说明 |
| --- | --- |
| 左侧:工单上下文 | 展示用户信息、订单、历史对话、政策标签;缺订单时显示补充入口 |
| 中间:AI 回复建议 | 展示建议回复、证据引用、可编辑区域、生成状态 |
| 右侧:Rubric 自检 | 展示准确性、完整性、风险、语气、政策符合度;不通过时给原因 |
| 底部操作栏 | 采纳、编辑、重试、升级;高风险状态下采纳禁用 |

### 必须覆盖的 UI 状态

不要只写正常态。至少检查:

- 默认态:首次进入看到什么。
- 加载态:等待接口/LLM 时显示什么,能不能取消。
- 空态:没有数据时展示什么引导。
- 错误态:接口失败、生成失败、解析失败。
- 权限态:无权限查看或操作。
- 边界态:字段缺失、结果过长、多个候选、冲突信息。
- 高风险态:需要人工确认、升级、二次确认。

## 图二:流程/状态图 -> 流程定义与状态机

流程图不能只复述用户路径,要写成研发可实现的节点与状态。

### 节点说明表

| Node | 类型 | 触发条件 | 输入 | 输出 | 成功流转 | 失败/异常流转 |
| --- | --- | --- | --- | --- | --- | --- |
| 获取上下文 | 工程 | 用户打开工单 | ticket_id | 工单上下文 | 进入生成建议 | 上下文缺失 |
| 生成回复 | LLM | 上下文完整 | 工单+政策 | 回复草稿 | Rubric 自检 | 生成失败 |
| 风险判断 | 规则/LLM | 回复生成后 | 回复+政策 | 风险等级 | 可采纳/需升级 | 失败则需人工 |

### 状态机写法

每个关键对象都要写状态枚举:

```text
DRAFT        - 草稿中
GENERATING   - 生成中
READY        - 可采纳
NEED_INFO    - 缺少关键信息
CONFLICT     - 政策或证据冲突
HIGH_RISK    - 高风险,必须升级
FAILED       - 生成失败,可重试
ACCEPTED     - 已采纳
ESCALATED    - 已升级人工
```

再写状态流转:

| 当前状态 | 触发 | 条件 | 下一状态 | 用户反馈 |
| --- | --- | --- | --- | --- |
| DRAFT | 点击生成 | 上下文完整 | GENERATING | 显示生成中 |
| GENERATING | 生成成功 | Rubric 通过 | READY | 展示回复建议 |
| GENERATING | 生成成功 | 缺订单信息 | NEED_INFO | 提示补充订单 |
| READY | 点击采纳 | 无高风险 | ACCEPTED | 写入回复区 |
| HIGH_RISK | 点击升级 | - | ESCALATED | 创建人工升级记录 |

## 一表 -> 字段、接口、埋点、测试

先判断表的类型,再转成 PRD v1 内容。

| 表类型 | PRD v1 转换 |
| --- | --- |
| 业务对象表 | 字段定义、枚举、校验、数据库/接口变更 |
| 评测样本表 | 测试集、验收 case、demo 场景 |
| 指标表 | Metric、目标值、埋点、看板口径 |
| 漏斗表 | 事件链路、转化率、掉点分析 |
| 权限表 | 角色、可见性、可操作性、越权处理 |

## PRD 反哺清单处理

来自前端探索的 PRD 反哺清单要逐条进入 PRD:

| 反哺项 | 写入位置 |
| --- | --- |
| 信息架构调整 | 页面/模块清单 |
| 流程缺口 | 流程图、节点表、状态机 |
| 状态补充 | UI 状态枚举、异常处理 |
| 边界条件 | 功能点详细说明、测试集 |
| 文案假设 | 文案定义、错误提示 |
| 指标变化 | Metric、埋点、验收标准 |
