# 阶段 2:ASCII 线框

目标:写代码前,用纯文本把**信息架构 + 每个区块放什么**敲定。改文本零成本,改整页代码很贵。

## 怎么画

- **从上到下逐区块**画,每块标清楚:区块名 + 里面有什么(标题文案/元素/图片/交互/CTA)。
- 标出**主 CTA** 出现的位置(落地页里 CTA 通常在 hero 一次、在社会证明之后再来一次)。
- 标出 3-5 个 sample 在界面中的位置:哪个 sample 用作默认场景,哪些 sample 用来展示异常、边界或高风险状态。
- 末尾附**移动端堆叠顺序**(最终必须响应式,先想清楚窄屏怎么排)。
- 不需要像素级精确,够用来对齐"放什么、什么顺序"即可。

## 落地页常见骨架(按需增删,别硬套)

```
┌─────────────────────────────────────────┐
│ NAV   logo            链接  链接   [CTA]  │
├─────────────────────────────────────────┤
│ HERO                                      │
│   大标题(一句话价值主张)                 │
│   副标题(给谁解决什么)                   │
│   [主 CTA]   次要链接                      │
│   ▷ 产品截图 / 演示                        │
├─────────────────────────────────────────┤
│ 价值点  ▣ 点1    ▣ 点2    ▣ 点3           │
├─────────────────────────────────────────┤
│ 功能/玩法  图 + 文(左右交替 2-3 段)      │
├─────────────────────────────────────────┤
│ 社会证明  logo 墙 / 数字 / 用户证言        │
├─────────────────────────────────────────┤
│ 定价 或 二次 CTA 区  [主 CTA]              │
├─────────────────────────────────────────┤
│ FOOTER  链接组 · 版权 · 社媒              │
└─────────────────────────────────────────┘
移动端堆叠:NAV(汉堡)→ HERO(CTA 全宽)→ 价值点(竖排)→ 功能(图上文下)→ 证明 → CTA → FOOTER
```

## AI 工单/客服界面骨架(示例)

当 PRD v0 是 AI 工单、客服、审核、运营助手等工作台类产品时,线框要优先把 samples 变成可切换 demo 场景和状态校验:

```
┌──────────────┬────────────────────────────┬──────────────────────┐
│ 左侧:工单上下文 │ 中间:AI 回复建议              │ 右侧:Rubric 自检       │
│ - 用户信息     │ - 建议回复正文                │ - 准确性/完整性/风险   │
│ - 订单/记录    │ - 引用证据/政策依据            │ - 不通过原因           │
│ - sample 切换  │ - 缺失信息提示                │ - 升级建议             │
├──────────────┴────────────────────────────┴──────────────────────┤
│ 底部操作: [采纳] [编辑] [重试] [升级]                              │
└───────────────────────────────────────────────────────────────────┘

Sample 状态:
- 正常可回复
- 缺少订单信息
- 政策冲突
- 高风险升级
- 生成失败
```
